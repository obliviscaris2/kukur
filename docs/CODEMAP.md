# KUKUR code map: where is what

This guide maps every feature of the game to the files that implement it, the config that tunes it, and the events it uses.

To answer "where does X live?" or "how do I change Y?", start with the feature index below, then open the files it names. The plot is in `docs/STORY.md`.

## The game in three sentences

KUKUR is a browser game (three.js r160, plain ES modules, **no build step**) about Khairey, a street pup in a cartoon Kathmandu valley built from real OpenStreetMap data and real terrain. The story begins on Kukur Tihar: the pup's mother (Aama) and brother (Bhai) are taken in a van, and the missions lead toward finding them. Between story beats, the city is an open world: traffic, people, dogs with territories, cats, birds, fireworks, water, weather, and a grimoire (bag, journal, diary).

## How it runs

```
index.html ─ import map ─► src/main.js ─► new App()            (src/app/App.js owns every system)
  App.boot():  World.init (terrain, tiles, props, sky…) → Pup → NpcManager → Traffic → Gameplay → UI
  App.#loop(): input → pup → camera → world → npcs → traffic → gameplay → hud → render (Post)
  States: loading → menu → intro (cinematic) → play ↔ paused        (App.state)
```
- **Serving:** `npm run dev` starts a static server on :5173, or Apache serves `/doggy/`. `sw.js` forces fresh modules.
- **Checking:** `npm run lint` (ESLint must stay clean) and `node tools/snap.mjs <url> <steps.json>` (headless Chrome; see "Testing").

## Common changes (where to go)

- **New mission:** add an object to `config/missions.js`. Step types are reach, collect, event and locked. New step logic goes in `Missions.update()` / `#event()`.
- **New journal task:** add one line to `TASKS` in `config/quests.js`, with an `event` name. If the event is new, emit it where the thing happens.
- **New festival day or greeting:** edit `FESTIVAL.days` and `FESTIVAL.lines` in `config/festival.js`.
- **More or fewer fireworks, diyos or rangoli:** `FESTIVAL.fireworks` and `FESTIVAL.decor`.
- **Busier or calmer streets:** `TRAFFIC.max`, `NPC.people.max`, `CATS.count`, `BIRDS.*.count`.
- **Different intent colours or rules:** `THREATS.colours` and `gameplay/disposition.js`; scan limits are in `SCAN.maxMarks`.
- **Camera feel:** `PUP.camera` (distance, pitch, `homeAfter`, `homeRate`).
- **Hillier or flatter valley:** `WORLD.terrain.exaggerate`. To re-sample the DEM, set `CELL`/`SIGMA` in `pipeline/terrain/build_terrain.py`, then run `npm run data:terrain`.
- **Floor patterns:** the `pave()` / `joint()` GLSL helpers and the ground, areas and road `fragMap`s in `render/materials.js`.
- **New creature:** copy the shape of `Cats.js` or `Birds.js`:
  - one `InstancedMesh`, with animation in the vertex shader through `toon({ vertexMain })`
  - population kept near the pup
  - construct and update it in `NpcManager`.
- **New cinematic beat:** see `scenes/PrologueScene.js`:
  - `shot()` and `card()` for cutscenes, `until(cond)` for player-driven steps
  - `app.storyCalm = true` for safety
  - clean up in `#end()`.
- **New hazard:** emit `damage`. Health, the hurt flash, the yelp and fainting all follow.

## Testing

`node tools/snap.mjs http://localhost/doggy/ tools/snaps/<script>.json` drives the real game in headless Chrome.
- **Step types:**
  - `wait` (seconds)
  - `until` (poll a JS condition, with `timeout`)
  - `eval` (run JS in the page; `window.__app` is the App)
  - `shot` (screenshot to `tools/snaps/out/`)
  - `key` (with `hold`)
- **Useful scripts:**
  - `smoke.json`: state plus perf (gpuMs, draw calls, triangles)
  - `prologue_full.json`: the whole story opening, end to end
  - `gameplay.json`, `climb2.json`, `art.json`
- `player_feel.json` (use `?noprologue`): whole-body dash collision, hop/landing, leaves/rubbish/cans, vehicle dimensions, impact recovery.
- `traffic.json` (use `?noprologue`): real-frame traffic movement/overlap/render audit, shopkeeper, police crossing, climbable stairs, waiting rider and schoolkid chase.
- `local_life.json` (use `?noprologue`): local dog silhouettes, live aura colours, a real charged-F stun, protected bystanders, house stair traversal, roof loot, generation in Patan/Bhaktapur/Boudha and performance.
- `npm run check:threats`: behaviour classification, line of sight, stun, actual catcher/dog attacks, bounded aura buffers, stacked stair navigation and all three dog rigs.
- `npm run check:traffic`: road graph, short segments, curves, following, police, rider merge, movable clutter and street interaction regressions.
- `npm run check:movement`: deterministic collision, frame-rate grounding, jump, animation-weight and actual-skeleton IK regressions.
- `npm run check:clearance`: continuous camera sweeps/returns, temple alignment, finite stupa domes, triangle contact, foundations, headroom and visible tread smoothing.
- `clearance.json` (use `?noprologue`): camera collision/speed, actual rendered ground and foundation geometry in Kathmandu, Patan, Bhaktapur, Boudha and Swayambhu.
- `camera_intro.json` (use `?noprologue`, optionally `&introAt=Swayambhu`): the actual aerial opening and return, checking every camera segment and final visibility. Intro waypoints follow the start elevation.
- `art_direction.json` (use `?noprologue&quality=low&verifyArt`): day/dusk/night/storm, real rendered hero/background contrast, local coats and NPC portraits. `tools/art-preview.html` shows saved original/updated captures.
- `mellow.json` (use `?noprologue&quality=low`): close open/closed eyes on the local breeds, then blossom in Patan, Boudha and Bhaktapur. `npm run check:graphics` checks shipped face geometry and the bounded blossom simulation.
- `magic.json` (use `?noprologue&quality=low`): Swayambhu gameplay and peepals, Patan jacarandas, Pashupati/Bhaktapur temple approaches and diyo detail. `npm run check:nature` checks geometry, streaming stability, slope grounding, lamp capacity and light fading. `tools/render-perf.mjs` measures GPU execution with timer queries and reports CPU submission separately.
- `npm run check:rendering`: dynamic-body broad-phase equivalence, bounded spatial batches/mist, finite street-light candidates and separated tread/riser faces in shipped temple GLBs. `tools/frame-profile.mjs` reports real frame cadence, rendered cadence and CPU costs; GPU time alone is not FPS.
- The snap runner exits nonzero on a timed-out condition, page exception, console error (including shader failures) or failed eval.
- **Budget** (weak iGPU, Intel HD 4600 class): about 8 ms GPU and about 220 draw calls in a busy street. Hide instanced meshes whose count is 0.
- Headless Chrome runs at a low frame rate. Hold keys longer in tests than a player would (the roar needs about 2.5 s of hold there).

## Gotchas worth knowing first

- **Height:** y = 0 is Basantapur's ground, not sea level, and not everywhere. Always use `world.heightAt(x, z)` or `world.terrain(x, z)`.
- **Coordinates:** +Z is **south**; heading is `atan2(dx, dz)`; Nepal drives on the **left**.
- **Prologue replay:** `settings.prologueDone` and `kukur.day.v1` (the calendar) live in localStorage. Use `?prologue` to replay the story, or clear storage.
- **Worker code:** `world/tiles/buildTile.js` and `world/terrain.js` must not touch the DOM.
- **Owned dogs:** territory dogs and story dogs (`owned = true`) are never despawned by `NpcManager`.
